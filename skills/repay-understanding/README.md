# repay-understanding

理解負債を返済する入口の skill。コード・仕様・設計・インフラ・PR・用語を、ユーザー自身の理解として取り戻すために説明する。

## 何ができるか

- 理解したい対象を1回呼ぶだけで、一次情報を読んだうえで説明する
- 説明の前に予想を1問だけ聞き、予想と事実のずれから説明を始める
- 状況に合わせて、言い直し・会話での説明・図解ページから手段を1つ選ぶ
- 説明の各項目に識別子を付け、「2-1をもっと」のように指定して深掘りできる

## 使い方

```
/repay-understanding <理解したい対象>
```

対象には、ファイルパス・PR番号・機能名・用語・直前の説明を渡せる。「理解したい」「わからない」と言うだけでも起動する。

同じ質問の繰り返しや、事実と違う前提での発言を Claude が検出したときは、1回だけ「いま扱うか」を尋ねる。同意するまで説明は始めない。

### 基本フロー

1. 対象のコード・設計書・PR などの一次情報を読む
2. 予想を1問だけ聞く。答えは自由記述で、「わからない」「問いを飛ばす」でも先へ進む
3. 説明の手段を1つ選ぶ
4. 根拠の場所を `path:line` で添え、識別子を付けて説明する
5. 識別子を指定されたら、その項目だけを具体例やコードで掘り下げる

### 説明の手段

| 状況 | 手段 |
|---|---|
| 直前の説明が伝わらなかった | 言い直し |
| 1つの概念・関数・設定・用語 | 会話での説明 |
| PR・Issue・長い設計文書・複数の部品にまたがる流れ | `explain-visually` の図解ページ |

## ファイル構成

- `SKILL.md` — 本体。起動の入口・問いの出し方・説明手段の選び方（Claude向け手順書）
- `README.md` — 本ファイル（人間向け）

## 前提・制約

- 図解ページを使う場合は `explain-visually` skill が必要。この skill は Skill ツールで `explain-visually` を呼ぶ
  - ページの検証に Google Chrome を使う
- 出力するファイルは `/tmp/` の下だけ。リポジトリや学習記録には何も書かない
- 理解度のクイズや採点はしない
- 混乱の検出は、会話に表れたサインに限る。黙って承認している状態は検出できない
