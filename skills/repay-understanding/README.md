# repay-understanding

理解負債を返済する入口の skill。コード・仕様・設計・インフラ・PR・用語を、ユーザー自身の理解として取り戻すために説明する。説明や図解を行う他の skill は、この skill が状況に合わせて選んで呼ぶ。

## 何ができるか

- 理解したい対象を1回呼ぶだけで、一次情報を読んだうえで説明する
- 説明の前に予想を1問だけ聞き、予想と事実のずれから説明を始める
- 状況に合わせて、言い直し・会話での説明・図解ページ・図・速習資料・学習資料・スライドから手段を1つ選ぶ
- これから決める計画や設計は、問いを重ねて詰めながら理解できる
- 説明の各項目に識別子を付け、「2-1をもっと」のように指定して深掘りできる

## 使い方

```
/repay-understanding <理解したい対象>
```

対象には、ファイルパス・PR番号・機能名・用語・直前の説明・これから決める計画を渡せる。「理解したい」「わからない」と言うだけでも起動する。

同じ質問の繰り返しや、事実と違う前提での発言を Claude が検出したときは、1回だけ「いま扱うか」を尋ねる。同意するまで説明は始めない。

### 基本フロー

1. 対象が既にあるものか、これから決めるものかを分ける。これから決めるものは `grilling` で詰める
2. 対象のコード・設計書・PR などの一次情報を読む
3. 予想を1問だけ聞く。答えは自由記述で、「わからない」「問いを飛ばす」でも先へ進む
4. 説明の手段を1つ選ぶ
5. 根拠の場所を `path:line` で添え、識別子を付けて説明する
6. 識別子を指定されたら、その項目だけを具体例やコードで掘り下げる

### 説明の手段

上の行ほど軽く速い。条件に合う行のうち、最も上のものを選ぶ。

| 状況 | 手段 |
|---|---|
| 直前の説明が伝わらなかった | 言い直し |
| 1つの概念・関数・設定・用語 | 会話での説明 |
| PR・Issue・長い設計文書・複数の部品にまたがる流れ | `explain-visually` の図解ページ |
| アーキテクチャ・データモデル・呼び出しの流れを図1枚で | `d2-diagram` |
| 他の読み手に渡す説明、実行例で確かめる理解 | `explainer` の速習資料 |
| 20分を超える体系的な学習 | `explainer-book` の学習資料 |
| 発表やウォークスルー | `d2-slides` |
| これから決める計画や設計 | `grilling` |

## 呼ぶ skill の出どころ

| skill | 出どころ |
|---|---|
| `explain-visually` | このリポジトリ |
| `d2-diagram`・`explainer`・`explainer-book`・`d2-slides` | explainer プラグイン |
| `grilling` | mattpocock-skills プラグイン |

`grill-with-docs`・`grill-me`・`teach`・`wait-what` は、プラグイン側で Claude から呼べない設定になっている。そのため、同じ働きを次のもので賄う。

| skill | 代わり |
|---|---|
| `grill-with-docs`・`grill-me` | `grilling` を直接呼ぶ。用語集や ADR は書かない |
| `teach` | `explainer-book` |
| `wait-what` | この skill に組み込んだ言い直しの手順 |

## ファイル構成

- `SKILL.md` — 本体。起動の入口・返済の種類・問いの出し方・説明手段の選び方・実行環境（Claude向け手順書）
- `README.md` — 本ファイル（人間向け）

## 前提・制約

- `explain-visually` の図解ページは、検証に Google Chrome を使う
- `d2-diagram`・`explainer`・`explainer-book`・`d2-slides` は次を前提にする
  - Node 24 以上。nodebrew で追加し、普段使う版は切り替えない
  - d2 0.9 以上。TALA レイアウトが同梱されていること
  - 作業場 `~/.local/share/repay-understanding/` の npm 依存と、Playwright の Chromium
  - 作り直す手順は `SKILL.md` の「explainer 系の実行環境」にある
- 出力するファイルは `/tmp/` の下と作業場だけ。プロジェクトのリポジトリには何も書かない
- 理解度のクイズや採点はしない
- 混乱の検出は、会話に表れたサインに限る。黙って承認している状態は検出できない
