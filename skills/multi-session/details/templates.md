# multi-session 雛形集

`{}`内は案件ごとに置換。プロジェクト固有規約（workflow skill名・人間ゲート・自動昇格条件）は各プロジェクトのCLAUDE.md/skillsから引く。

## 1. 起動プロンプト（ユーザーへ渡す）

セッション名も併せて提示: `#{チケット番号} {チケットタイトル}`

```
{workflow skill名}（{skillパス}）を前提に、{チケットID群}に着手する準備セッションです。

これは起動確認です。作業には着手せず、以下だけを返答して待機してください。

- セッション名: #{チケット番号} {短縮タイトル}
- 対象チケット: {チケットID群}
- 状態: 起動完了、詳細指示待ち

詳細な作業指示（完了条件・ブランチ名・不変条件・停止基準等）は後ほどコーディネーターセッションから SendMessage で送ります。それまでファイルの読み書き・Bashコマンド実行・外部ツール参照・worktree作成などの作業は一切開始しないでください。
```

## 2. 本指示（SendMessageで送る）

```
{workflow skill名}（{skillパス}）に従い、{チケットID群}に着手する。待機は解除。ここから作業開始してよい。

## 対象チケット{複数まとめる場合: （このN件をまとめて1つのPRとする特別運用。根拠と共に明記）}

- {チケットID}: {タイトル}

各チケットの詳細は {参照手段。例: Atlassian MCP（cloudId: xxx）でgetJiraIssue} で全文を読むこと。

## ブランチ

`{ブランチ名}` を新規作成して作業する（{workflow skill}の該当Stepに従い、worktreeも作成する）。

## ベース情報

- ベースブランチ: {main等}
- {その他接続情報: cloudId等}

## 完了条件（逐語）

{各チケットの完了条件をチェックリスト形式で逐語転記}

修正方針がこれら全項目をカバーすることを実装前に検証すること。未カバー項目は実装に組み込むか、コーディネーターへ返すこと。

{コーディネーター側へ切り出す項目があれば明記。例: prod書き込みはコーディネーター承認必須のため、コード対応と実行手順の準備までを担当し、実行自体は持ち帰ること}

## 委譲タイプ・品質チェック

{workflow skillの委譲タイプを明記。実施すべきレビュー・E2E等の完了定義を含める}

## 不変条件

- mainブランチを動かさない／マージしない（マージはユーザー最終確認後にコーディネーターが実施する）
- 作業ブランチ外への破壊的操作をしない
{案件固有の禁止事項}

## 停止基準

以下に該当したら作業を止め、論点と選択肢を明記して私（コーディネーターセッション）に返信すること（返信は必ずSendMessageで行う。プレーンテキスト出力では届かない）。

**AskUserQuestionは使用禁止**。ユーザーへの確認が必要な論点は、すべてSendMessageでコーディネーターへ送ること。バックグラウンドセッション内の質問ダイアログはユーザーの目に入らず失効し、質問表示中はSendMessageの受信もできなくなるため、コーディネーターからは停止と区別できなくなる。

- 設計未確定の確認が必要な場合
- 不可逆操作が必要な場合
- {プロジェクトのworkflow規約の自動昇格条件を逐語列挙}
- {レビュー収束失敗等の規定}

完了したらPR番号と検証結果（テスト実行ログ・レビュー結果等の一次情報）をSendMessageで報告すること。
```

## 3. 承認伝達（判断回答の返信）

```
閣下（ユーザー）から回答があった。

1. {論点}: {回答。承認の場合「自動昇格条件Nの承認として扱う」等、根拠区分も添える}
2. {論点}: {回答}

{未回答の論点があれば}: {論点}はまだ回答がない。保留のまま{暫定の進め方}で進めてよい。正式な回答が来たら改めて連絡する。
```

## 4. 生存確認・催促

```
{N回連絡したが返答がない状態。}今すぐ現在の状態（{確認したい点}、何か詰まっているか、単に作業中で手が空いていないだけか）をこのセッションへ報告してほしい。作業中で手が離せないなら、その旨だけでもよいので一言返してほしい（返信はSendMessageで。プレーンテキスト出力では届かない）。
```

## 5. 完了受領・後片付け

```
{PR番号}をマージした（マージコミット: {SHA}）。

後片付け:
- {破壊的コマンドで消すもの}は{ユーザーが実行済み／ユーザーへ依頼中}
- worktree `{worktreeパス}` は{workflow skill}の後片付けStepに従い削除してよい／こちらで削除した

{残る確認事項があれば列挙}
```
