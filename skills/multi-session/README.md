# multi-session

複数の独立Claude Codeセッションを並列稼働させ、1つのコーディネーターセッションが統括する運用のskill。

## 何ができるか

- 複数チケット・複数タスクを独立セッションへ分散し並列実行
- コーディネーター経由の進捗確認・承認伝達・マージ集約（ユーザーは各セッションを直接見ずコーディネーターに聞けばよい）
- レートリミット分散（独立セッションはAPI上限が別枠。サブエージェントは親と共有）

## 使い方

コーディネーターにしたいセッションで:

```
/multi-session
```

または「並列セッションで進めて」「複数セッションに分けて」等の依頼で自動発火。

### 基本フロー

1. コーディネーターが起動プロンプトを提示 → ユーザーが別ターミナルでセッション起動・命名（`--name "#123 タイトル"` or `/rename`）
2. コーディネーターが`ListAgents`で発見 → `SendMessage`で本指示送信 → ワーカー着手
3. 進捗・判断確認はコーディネーター経由。マージ・prod操作もコーディネーターが実施
4. 破壊的コマンド（docker rm等）はhookブロック時ユーザーへ提示される

## ファイル構成

- `SKILL.md` — 本体。ライフサイクル5段階＋落とし穴5件（Claude向け手順書）
- `details/templates.md` — 雛形5種（起動プロンプト・本指示・承認伝達・生存確認・完了受領）
- `README.md` — 本ファイル（人間向け）

## 前提・制約

- Claude Code v2.1.224以降、macOS/Linux（cross-session messaging要件）
- ワーカー起動はユーザーの手動操作（コーディネーターから独立セッションは起動できない）
- レートリミット等ワーカー内部エラーはコーディネーターから検知不可 → 無応答時は画面目視
- ワーカーはユーザーへ直接質問しない（本指示で禁止）。質問はすべてコーディネーター経由 → ユーザーはコーディネーターの画面だけ見ればよい
- ピア経由の承認は無効。ユーザーopt-in必要な機能（Ultracode等）は各セッションへ直接入力
