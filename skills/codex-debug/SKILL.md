# Codex Debug Skill

OpenAI Codex CLI を Agent tool（バックグラウンド）で実行し、エラーの根本原因究明・デバッグを行う。`codex exec --full-auto` による自由形式の調査で、Codex 処理中もユーザーと会話を継続できる。

## 手順

STEP 1 → STEP 3 を上から順に実行する。

### STEP 1: 症状を集める
次を埋めて、STEP 2 の依頼文を組み立てる材料にする。

| 項目 | 内容 |
|------|------|
| エラー内容 | メッセージ・スタックトレース |
| 期待 / 実際 | 期待動作と実際の動作 |
| 再現・範囲 | 再現手順・対象ファイル |

依頼文の型（症状に応じて1つ選ぶ）:
- **ランタイムエラー**: `以下のエラーをデバッグ: {エラーメッセージ}。スタックトレースを解析し、根本原因を特定`
- **ロジックバグ**: `期待動作: {期待}、実際の動作: {実際}。ロジックの問題を調査`
- **パフォーマンス問題**: `処理が遅い箇所を特定。ボトルネック分析と改善案を提示`

共通付記（選んだ型の末尾に必ず付けて `{依頼文}` を組み立てる）: `根本原因は因果の機序として1文で言語化し、真因が起きていないことを直接測る検証方法と、同じ機序が起こり得る同型箇所の grep 結果（該当なしなら探索条件）を併せて出力せよ`

この付記で依頼側にも完了条件を伝え、STEP 3 の「デバッグ完了の定義」（合格基準）と二段構えにする。

### STEP 2: 単一 Agent で発行する
`run_in_background=true` で1つの Agent を発行する。`{依頼文}` に STEP 1 で組み立てた文（選んだ型＋共通付記）を入れる。

```
Agent(
  name="codex-debugger",
  description="Codexデバッグ実行",
  run_in_background=true,
  prompt="Bashツールで以下のコマンドを実行してください（timeout: 600000）。結果のstdoutをそのまま返してください。

codex exec --full-auto '{依頼文}'
"
)
```

### STEP 3: 完了後に報告する
完了通知を待ち（その間ユーザーと会話継続可）、stdout を下の DebugResult に流し込んで報告する。報告前に「デバッグ完了の定義」の3条件を満たしているか確認し、欠けている条件は追加調査で埋める。

## デバッグ完了の定義（STEP 3 の合格基準）

3条件すべてを満たしたときに完了とする。

| 条件 | 内容 |
|------|------|
| 真因の言語化 | 真因を機序として1文で言語化する（「Xが起きていた」という症状の裏返しではなく、「AがBのためCになる」という因果で書く） |
| 真因ベースの検証 | 「真因が起きていないこと」を直接測る指標で検証する（症状指標が構造的に欠陥を検出できないタイプがあるため、症状消失の確認には真因側の検証を併記する） |
| 水平展開の列挙 | 同じ機序が起こり得る同型箇所を機械的に列挙する（grep 等で網羅的に洗い出し、該当なしならその探索条件を示す） |

## DebugResult（STEP 3 で使う素材）
| フィールド | 説明 |
|-----------|------|
| 症状 | 報告されたエラー・問題の要約 |
| 原因 | 特定された根本原因（機序として1文で言語化する） |
| 調査過程 | 調査手順と確認した内容 |
| 解決策 | 修正方法・コード変更案 |
| 完了検証 | 真因が起きていないことを測る指標と、その確認結果 |
| 水平展開 | 同じ機序が起こり得る同型箇所の列挙（該当なしなら探索条件） |
| 予防策 | 再発防止のための提案 |
